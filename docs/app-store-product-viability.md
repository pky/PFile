# PFileをApp Storeへリリースする価値の検証

最終更新: 2026-07-11

## 結論

判定は「Go」とする。ただし、大規模な収益を狙う製品ではなく、無料・広告なしのニッチな読み取り専用メディアブラウザとして公開する。

PFileは、汎用ファイルマネージャーや高機能動画プレイヤーとして競合へ正面から勝てる状態ではない。しかし、次の用途へ絞ればApp Storeへ出す価値がある。

> NAS、Files、写真に散らばった個人動画を、フォルダ構造のまま探し、あとで見るリストと履歴からすぐ再開できる、iPhone / iPad向けの読み取り専用メディアブラウザ

個人利用とポートフォリオを目的に含むため、P0を完了して公開する価値は十分ある。市場検証目的の外部TestFlight募集は必須にせず、一般公開後の匿名Analytics、App Store Analytics、レビュー、問い合わせから改善方向を判断する。

## 市場の状況

NAS動画再生とファイル閲覧の市場には、すでに強い競合がいる。

| アプリ | 強み | PFileが正面対決すべきでない領域 |
|---|---|---|
| [Infuse](https://apps.apple.com/jp/app/infuse/id1136220934) | SMB、Plex等、多形式、メタデータ、字幕、複数Apple端末、洗練された再生 | 映画・TVライブラリの総合体験 |
| [VLC media player](https://apps.apple.com/jp/app/vlc-media-player/id650377962) | 無料、多形式、SMB等、字幕、履歴、再生位置、幅広い端末 | 無料・対応形式数・知名度 |
| [nPlayer](https://apps.apple.com/jp/app/nplayer/id1116905928) | SMB/NFS/クラウド、字幕、再生調整、ファイル操作 | 高機能プレイヤーとプロトコル数 |
| [FE File Explorer Pro](https://apps.apple.com/jp/app/fe-file-explorer-pro/id499470113) | SMB/クラウド、転送、コピー、管理、約6000件の評価 | 汎用ファイル管理 |
| [FileBrowser Professional](https://apps.apple.com/jp/app/filebrowser-professional/id854618029) | ファイル操作、同期、企業利用、広い接続先 | 業務向けファイル管理と同期 |
| [NAS Media Viewer](https://apps.apple.com/jp/app/nas-media-viewer/id6759468790) | SMB/Plex/Jellyfin、履歴、お気に入り、再生しながら閲覧 | NAS専用メディアライブラリ |

一方で、2025年以降もSMB再生へ特化した新しい小規模アプリが複数公開されている。これは需要が完全になくなった市場ではないことを示す。ただし、単に「SMB動画を再生できる」だけでは差別化にならない。

## PFileにリリース価値がある理由

### 1. 解いている課題が実在する

- PlexやJellyfinをNASへ導入したくない利用者がいる
- 映画・TV番組としてメタデータ整理するより、既存フォルダ構造から探したい個人動画がある
- NAS、Files、写真を行き来すると、視聴履歴と「あとで見る」の管理が分断される
- iPadでネットワーク動画を探し、途中から再開する操作は標準Filesだけでは弱い

### 2. 実装に簡単には代替できない技術的価値がある

- SMB上の動画をダウンロードせず再生する
- AVPlayerとMobileVLCKitを形式で使い分ける
- SMB Range読み出し、シーク、サムネイル、キャッシュを扱う
- NAS上の動画にも履歴、再生位置、手動リストを適用する
- iPhone / iPadの縦横UI、Files、フォトライブラリを同じ操作体系へ寄せる

これらはポートフォリオとして十分に説明価値があり、実利用でも単純なサンプルアプリを超えている。

### 3. 「少機能」が利点になり得る

コピー、移動、削除を持たないことは、汎用ファイラーとしては弱点だが、読み取り専用ブラウザとしては誤操作でNAS上のデータを失わない利点に変えられる。

ただし、App Storeの説明とアプリ内表現で「ファイル管理」ではなく「閲覧・再生・リスト整理」であることを明示する必要がある。

## 現状のままでは価値が伝わらない理由

### 1. 一言で伝わる差別化が弱い

「SMB対応」「多形式再生」「履歴」は競合も持っている。現在の説明だけでは、利用者がInfuse、VLC、nPlayerではなくPFileを選ぶ理由が見えない。

訴求の中心を次へ限定する。

- メディアサーバーの構築が不要
- フォルダ構造をそのまま使える
- 個人動画を手動リストで整理できる
- NASでも前回位置からすぐ再開できる
- 読み取り専用なので元ファイルを壊さない
- 日本語で迷わず使えるiPad中心UI

### 2. 信頼性が価値そのものになる

NASアプリでは、再生開始、シーク、復帰、サムネイルのどれかが頻繁に止まるだけで継続利用されなくなる。機能数より先に、現在のSMBサムネイルクラッシュと長時間再生を収束させる必要がある。

### 3. 広告モデルが利用者の期待と衝突する可能性がある

NASや個人写真を扱うアプリでは、第三者広告SDKと解析SDKが信頼を下げやすい。さらに対象市場が狭いため、バナー広告の収益規模は大きくなりにくい。

1.0は完全無料・広告なし・課金なしで公開する。Firebase AnalyticsとCrashlyticsは、利用者が同意した場合だけ、匿名化した利用傾向と障害情報の取得に使用する。広告連携、IDFA、クロスアプリ追跡は行わない。

収益性の検証は1.0の目的から外し、安全性、安定性、実利用の把握を優先する。

## 想定する最初の対象ユーザー

次をすべて、または多く満たす人へ絞る。

- Synology、QNAP、自作NAS、Windows共有等に動画を保存している
- iPadまたはiPhoneで自宅内視聴する
- Plex / Jellyfinの構築やメタデータ整理をしたくない
- 映画だけでなく、講義、学習、家族動画、録画、資料動画等をフォルダで管理している
- 見る動画を手動リストへ分け、途中位置から再開したい
- NAS上のファイルをアプリから変更・削除する必要はない

この条件に合わない一般ユーザーへ広く訴求すると、競合との機能差で不利になる。

## 公開後の価値検証

市場検証目的の外部TestFlightは行わない。App Store公開後に、利用者が同意した匿名AnalyticsとAppleの集計情報から次を確認する。

### 収集する指標

- SMB / ローカル / 写真の利用比率
- 再生開始と再生失敗の比率
- 履歴再開が使われる比率
- リスト追加が使われる比率
- サムネイル失敗の形式別傾向
- App Storeの継続セッション、削除、クラッシュ傾向
- レビューと問い合わせで繰り返し現れる要望

### 公開継続の判断

初回公開から90日を一区切りにする。少人数でも履歴再開やリストが継続利用され、重大クラッシュとデータ事故がなければ開発を継続する。利用が単発再生だけに偏る場合は、差別化機能より再生基盤へ絞るか、ポートフォリオとして保守のみへ移行する。

## No-Goまたは方向転換の条件

- 接続設定で半数以上が離脱する
- 競合との差を全員が認識できない
- リストと履歴が使われず、単発再生だけで終わる
- SMB再生の安定性が競合より明確に低い
- 開発者本人以外に週次利用者が残らない

この場合でも開発実績としての公開価値は残る。商用アプリとしての追加投資を止め、オープンソースのポートフォリオまたは個人用アプリとして位置づける。

## 最終判断

### 個人利用・ポートフォリオとして

Go。すでにApp Store公開を目指すだけの技術的厚みがある。公開プロセス、プライバシー、匿名Telemetry、運用まで完遂すること自体にも価値がある。

### 小規模なニッチ製品として

Go。「読み取り専用」「フォルダ構造」「手動リスト」「履歴再開」「サーバー不要」へ絞り、無料・広告なしで公開後の利用傾向を匿名Analyticsから確認する。

### 大きな収益を狙う製品として

対象外。1.0では収益化を目的にせず、無料・広告なしを信頼上の特徴として扱う。

## 競合から取り入れる機能

### 1.0へ入れる候補

#### 現在のフォルダ内検索

多くの競合が検索を備えており、大きなNASでは一覧を辿るだけでは目的の動画へ到達しにくい。1.0では再帰的なNAS全体検索まで行わず、読み込み済みの現在フォルダをファイル名で絞り込む最小実装を推奨する。

これはネットワーク負荷が増えず、既存一覧のフィルタとして実装できるため、1.0を大きく遅らせにくい。

### 1.1で優先する機能

#### フォルダをリストへ追加する動的リスト

お気に入りフォルダという別機能は作らず、既存のメディアリストへフォルダ参照を追加できるようにする。フォルダ追加時に配下のファイルを固定コピーせず、リスト表示時にフォルダの現在内容を解決する。

これにより、フォルダへ後から追加された動画・画像も同じリストへ自動的に現れ、リストが「手動で選んだファイル」と「継続的に見るフォルダ」の両方を扱える。

初期仕様:

- ファイルとフォルダを同じリストへ追加できる
- フォルダは`sourceID`とパスで参照する
- リストを開いた時にフォルダ直下の動画・画像を動的に取得する
- フォルダへ追加された動画・画像は次回読み込み時に自動で現れる
- フォルダ外へ移動または削除された動画・画像は次回読み込み時に自動で消える
- サブフォルダは最初は再帰展開せず、フォルダ項目をタップして移動する
- 明示追加したファイルとフォルダ由来ファイルが重なる場合は同一項目として表示する
- フォルダ由来の表示から消えても、同じファイルを単体で明示追加している場合はリストに残す
- 削除済み・移動済みフォルダは無言で消さず、参照切れとして再設定またはリストから削除できる
- SMB接続不能時は既存のファイル項目を壊さず、フォルダ項目だけ再読み込み可能なエラー表示にする

サブフォルダを含む再帰的な平坦化は、大規模NASで通信量、待ち時間、重複、並び替えが問題になるため初期実装には入れない。必要性が確認された場合だけ、フォルダ項目ごとのオプションとして追加する。

#### ホームの「続きを見る」

履歴タブはすでにあるが、直近2〜5件をホームへ出すことで「途中からすぐ再開」という中核価値が初見でも伝わる。新しいデータモデルは不要で、既存履歴を再利用する。

#### 再生速度

講義、学習、録画、確認用動画では0.5〜2.0倍程度の速度変更が有用で、nPlayerやVLC等では標準的である。映画向けの高度なメタデータよりPFileの対象用途に合う。

### 1.2以降で検討する機能

- Picture in Picture
- BonjourによるNAS候補の発見
- 音声トラックと字幕トラックの選択
- A-Bリピート

### 取り入れない、または優先しない機能

- お気に入りフォルダ
- コピー、移動、削除、リネームなどの書き込み操作
- 多数のクラウドサービス接続
- Plex / Jellyfin相当の映画メタデータ取得
- オフラインダウンロードと双方向同期
- Chromecast
- 高度な字幕ダウンロード・編集

これらは強い競合の得意領域であり、読み取り専用・サーバー不要・手動整理というPFileの焦点を弱める。

お気に入りフォルダは、フォルダを開く導線としてはメディアリストと役割が重なり、利用者に「どちらへ保存すべきか」という判断を増やすため追加しない。「フォルダへ新しく追加されたファイルも自動的に含めたい」という用途は、独立機能ではなく上記の動的リストで扱う。

## 次の行動

1. App Storeリリース準備のP0を継続する
2. 広告・課金を削除し、同意式の匿名Analyticsへ整理する
3. 内部配布または実機Release構成で技術的な配布確認だけを行う
4. 無料・広告なしで一般公開し、匿名Analyticsとレビューから改善順を判断する
5. ストア説明では「ファイラー」を主語にしない
